## 问题 1：这个 fork 在上游 OpenMAIC 之上加了哪些数字人 / TTS / 实时老师功能？

### Takeaway
上游 OpenMAIC（v1.1.1/v1.1.2）**完全没有数字人**，只有 11 种 TTS 提供方，可在生成课件时为每个场景预生成旁白音频。fork 新增了整套“AI 老师”层：Anam 实时数字人讲旁白和回答问答、教师数字分身工作室（照片和声音克隆）、绿幕抠像融入幻灯片、HeyGen 预渲染老师片段（只在本地，未部署）、浏览器 `speechSynthesis` 作为默认免费声音，以及服务端的开关和计费防护。fork 还**有意不配置任何服务端 TTS**。

## 问题 2：现在的架构：哪些模块处理 Anam / ElevenLabs / 其他供应商，会话怎么建，语音怎么驱动，怎么和幻灯片同步，重连和计费怎么做？

### Takeaway
现在只接了 **Anam 一家实时数字人**，走“服务端换会话令牌 → 浏览器 WebRTC 拉流”的模式。Anam 自带的 LLM 被关掉（`llmId: CUSTOMER_CLIENT_V1`），只念客户端发过去的**文本**：一次 `talk(text)` 一句旁白，Anam 自己做 TTS 和口型。**ElevenLabs 没有被直接调用**，而是作为导入到 Anam 组织里的音色（印尼语、中文），由 Anam 代调。英语音色和声音克隆用的是 Cartesia sonic-3.6。播放引擎是逐条动作串行执行：一句话说完（Anam 回 `endOfSpeech`）才执行下一个动作（聚光、激光笔、白板），以此和幻灯片同步。代码里没有按分钟计费的账本，只有会话 30 分钟上限、每节课最多自动重连 3 次、角色和租户开关，以及（最新分支上的）按课程声音设置做的服务端计费防护。

### Cited Findings
**会话创建（服务端令牌交换）**
- `POST /api/avatar/session` 在服务端用 `ANAM_API_KEY` 调 `https://api.anam.ai/v1/auth/session-token`。请求体是 `personaConfig: {name:'Teacher', avatarId, voiceId, llmId:'CUSTOMER_CLIENT_V1', languageCode, maxSessionLengthSeconds:1800}`、`sessionOptions:{videoQuality:'high'}`，只把 `sessionToken` 返给浏览器，API key 不出服务端 — [app/api/avatar/session/route.ts#L32-L113](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/app/api/avatar/session/route.ts#L32-L113)
- `GET /api/avatar/session` 只是探针，返回 `{enabled, defaultOn?}`，不建会话、不计费 — [route.ts#L37-L44](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/app/api/avatar/session/route.ts#L37-L44)；[lib/avatar/live-avatar-availability.ts#L1-L38](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/live-avatar-availability.ts#L1-L38)
- 视频规格：Cara 4 模型默认 1152x768；注释写明显式指定尺寸会被旧模型拒绝 — [route.ts#L97-L101](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/app/api/avatar/session/route.ts#L97-L101)。Anam 只有头、肩和上胸的取景，“session video is 1152x768 or 768x1152 crops of the same source” — [CLAUDE.md#L595-L597](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L595-L597)

**浏览器端 SDK 封装与语音驱动**
- `lib/avatar/lecture-avatar.ts` 是一个模块级单例：
  - `createClient(sessionToken, { disableInputAudio: true })`，**不开麦克风**，打断由应用自己处理；
  - `streamToVideoElement(videoId)` 拉流；
  - 收到 `DATA_CHANNEL_OPEN` 才算 ready；
  - 每句 `client.talk(text)`，收到 `MESSAGE_STREAM_EVENT_RECEIVED` 且 `role==='persona' && endOfSpeech` 时这句结束；
  - 用 inflight 计数处理“新的 talk 打断旧句、旧句结束事件晚到”的情况；
  - `interruptPersona()` 打断；
  - `CONNECTION_CLOSED` 置为 error。

  来源：[lib/avatar/lecture-avatar.ts#L191-L284](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/lecture-avatar.ts#L191-L284)
- 文件头注释：“The persona runs with Anam's LLM disabled, so it only says what `speak()` sends. Any failure leaves `isReady()` false and the engine falls back to its reading timer, so an avatar problem never blocks a lesson.” — [lecture-avatar.ts#L1-L9](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/lecture-avatar.ts#L1-L9)
- 实测的事件行为（SDK 4.27.1）：persona 的流事件逐词到达、与音频同步，句末是一个带 `endOfSpeech` 的空事件；`TALK_STREAM_INTERRUPTED` 在 `interruptPersona()` 后不会触发 — [lecture-avatar.ts#L216-L223](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/lecture-avatar.ts#L216-L223)；[CLAUDE.md#L580-L583](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L580-L583)
- 文本来源有两类：
  - 课件里预写好的旁白，即 speech 动作的 `text`；
  - 学生提问时，教师 agent（OpenMAIC 的 discussion/LLM）生成的回复。`companion-speech.ts` 包装了 `discussionTTS`，把老师的回复段落交给数字人说。

  来源：[lib/avatar/companion-speech.ts#L1-L24](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/companion-speech.ts#L1-L24)
- 课件生成用的 LLM：所有调用都经 `MODEL_ROUTES` 路由到 `deepseek-flash`（关闭 thinking）。一节 6 场景的课约 1 分钟生成完，约 15 秒后可播第一个场景 — [CLAUDE.md#L347-L349](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L347-L349)

**与幻灯片 / 白板动作同步**
- 引擎对每个 speech 动作的声音来源有优先级，依次是：
  1. 预生成音频 `audioPlayer.play(audioId)`；
  2. 预渲染老师片段 `prerenderedTeacher.clipFor`；
  3. 实时数字人 `lectureAvatar.isAvailable()` → `playAvatarSpeech`；
  4. 浏览器声音或阅读计时器 `playLessonVoiceOrTimer`。

  来源：[lib/playback/engine.ts#L708-L737](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L708-L737)
- spotlight 和 laser 是即发即走的视觉效果，通过 `queueMicrotask` 立即执行下一动作。speech 动作要等说完（`onSpeechEnd` → `processNext`）才继续，所以“说完一句再执行后面的白板、聚光动作”就是同步机制 — [engine.ts#L739-L760](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L739-L760)；[engine.ts#L1097-L1135](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L1097-L1135)
- 安全超时 = 估算朗读时长 × 2 + 5 秒。播放速度对数字人无效（Anam 语速不可调）— [engine.ts#L1114-L1117](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L1114-L1117)；`62ce8e38` “1x with the live teacher (#36)”
- 暂停时打断数字人，继续时**整句重说**（不是从断点续说）：`avatarPausedSpeech` → `playAvatarSpeech` — [engine.ts#L300-L330](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L300-L330)；[CLAUDE.md#L584-L585](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L584-L585)
- 学生在课中提问（打字或语音，ASR 在应用侧，`asrLanguage` 可设 `id-ID`）时，引擎先取消当前讲解句，再由数字人说老师的回答。7 秒无声后自动恢复讲解；白板状态在问答开始时快照、结束时恢复 — [CLAUDE.md#L293-L301](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L293-L301)；[lib/whiteboard/live-session-snapshot.ts](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/whiteboard/live-session-snapshot.ts)

**显示形态（透明背景需求）**
- Anam 流**没有 alpha 通道**。fork 的做法分两步：
  - 制作分身时，在浏览器里用 MediaPipe 人像分割把照片背景换成绿幕；
  - 课堂里用 WebGL 抠像（Anam cookbook 的 shader）把分身画到幻灯片右下角，高度为舞台的 45%。

  显示模式有 `window` 和 `blend` 两种，可抠像时默认 `blend`。2026-10-05 实测 Anam 输出的绿色很平（std-dev < 2）— [CLAUDE.md#L273-L280](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L273-L280)；[CLAUDE.md#L457](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L457)；[lib/avatar/chroma-key.ts](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/chroma-key.ts)
- 同一个 `<video>` 元素持久存在，Pro 编辑切换时停到屏幕外，会话保留 60 秒后重新挂回 — [lecture-avatar.ts#L57-L66](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/lecture-avatar.ts#L57-L66)；[CLAUDE.md#L300-L301](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/CLAUDE.md#L300-L301)

**重连**
- 每节课最多自动重连 3 次，退避 2、5、10 秒；只有下一句旁白要说时才触发 `ensureReady`。按 Play 时，每句最多等数字人 12 秒（`AVATAR_READY_TIMEOUT_MS = 12_000`），超时就改用浏览器声音 — [lib/avatar/avatar-retry-policy.ts#L9-L12](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/avatar/avatar-retry-policy.ts#L9-L12)；[engine.ts#L65](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/lib/playback/engine.ts#L65)

## 问题 3：有没有预渲染模式，还是只有实时？每页 / 每个场景的 TTS 是否预生成？

### Takeaway
有过三条预渲染路线：
1. **HeyGen Avatar V 预渲染老师片段**：本地原型，技术上可行，但未部署，Chrome 专用；
2. **Anam 离线 Avatar Videos API**：成本模型里的“经济档”，目前只用于音色试听；

## 问题 4：团队实际试过哪些供应商？文档和提交里有哪些成本、延迟和对比数据？

### Takeaway
实际接入或实测过的有：**Anam**（实时 + 分身 + 离线渲染）、**ElevenLabs**（经 Anam 导入的音色，以及直接调用的离线旁白）、**Cartesia**（Anam 自带音色和克隆引擎）、**HeyGen Avatar V**（预渲染片段，有实测单价）、浏览器 `speechSynthesis`。调研过但没接入的有：Seedance 2.5、HeyGen LiveAvatar、Simli、D-ID、Tavus Phoenix-4、阿里灵眸、腾讯、百度、TalkingHead/MetaPerson/Avaturn、fal LatentSync、自建 LatentSync/MuseTalk。提议过但没开始的质量对比：HeyGen、MiniMax H3、OmniHuman 1.5、LongCat-Video-Avatar。远期路线是 Unreal MetaHuman 本地渲染。

### Cited Findings

- 部署约束：新代码不得增加只能跑在 Vercel 或 Cloudflare 上的依赖；公立学校阶段学生数据必须在印尼境内；外部 AI 统一经过我方网关（额度账本） — [tech-stack-and-cost.md §1, §4](https://github.com/Kunbyte-AI/maic-avatar/blob/deploy/prod-diagram-fix/dev-and-design/tech-stack-and-cost.md)

### Inferences：替代供应商的需求清单（从代码反推）

**实时档（必须）**
1. 浏览器端 WebRTC（或同等低延迟）流，能挂到任意 `<video>` 元素上，并且支持换挂载点（`mountVideo` / `parkVideo` 模式）。
2. **服务端签发短期令牌**，API key 不进浏览器。
3. **关闭内置 LLM、按文本驱动（BYO text / custom LLM）**，每次发送一句。
4. 可靠的“说完”事件，以及打断 API（`interrupt`），打断后状态要干净。
5. 断线事件，并能快速重建会话。会话时长上限最好 ≥45 分钟，至少要能续接。
6. 可设会话时长上限，或由服务端强制结束，用来防止失控计费。
7. 支持 en / id / zh 音色，并支持导入或克隆声音（含 id）。
8. 能用照片（或短视频）创建自定义形象，用于教师数字分身。

**实时档（加分）**
- 绿幕或透明背景输出（现在靠绿幕照片 + WebGL 抠像实现）。
- 半身或全身取景、手势（团队的明确诉求，Anam 做不到）。
- 词级时间戳。
- 可调语速。
- 外部音频输入做口型（这样可以统一用 ElevenLabs 或自有 TTS）。

**预渲染档（必须）**
1. API 批量渲染，**接受我方音频做口型**，保证与录音版同一把声音。
2. 输出**能在 Safari 和 Android 播放的格式**。
3. 书面的缓存、回放和再分发权利（包括课堂主机离线播放）。
4. 下载 URL 过期前能被我们转存（现在把 1 小时过期当作常态）。
5. 句子级切片，或带时间戳的整段视频，以便映射到 speech 动作。

**基础设施**
- 每人 1 个会话、全局并发上限、消费上限和告警（tech-stack §7 要求“Anam、HeyGen 确认是否支持消费上限和告警”）。

### Gaps
- 现在没有把供应商抽成 provider 接口的代码。换供应商时，是加一个 `lib/avatar/<vendor>-avatar.ts` 并按 env 切换，还是重写单例，需要设计决定。
- 当前没有用到 Anam 的 ASR 或对话模式（`disableInputAudio: true`）。如果新供应商的计费把 ASR 和 LLM 打包在一起，要确认能否只买“TTS + 口型”部分。

### Inferences：建议给供应商比价用的基准
- **实时**：一节课约 23–27 分钟数字人口播（会话时长约等于课长 45 分钟，因为 Anam 会话一直开着，包括测验和练习时间），每观看者一路流。按 credits 计，比价单位用“$/会话分钟”，**注意要区分“说话分钟”和“连接分钟”**。
- **预渲染**：每节课每种语言约 23–27 分钟渲染（全出镜），A-roll/B-roll 25% 出镜时约 6–7 分钟。课程目录是 G7+G10 数学共 20 节 × 3 种语言 = 60 节，加 20 节 SDH，生产环境共 80 节；设计文档还提到 79 节课要预渲染。
- **TTS**：每节课每种语言约 18–21k 字符（英语、印尼语），中文约 5k 字。80 节课全量约 1.5M 字符一次性。
- **课堂投屏**：一间教室一路流（老师端），学生跟随端不拉流，所以“课堂投屏”的并发 = 同时上课的班级数，不是学生数。

### Gaps
- 当前实际的实时数字人使用量（分钟/日、并发峰值）没有任何记录，代码里也没有计量。
- 60% 讲解占比未确认。按本地统计，45 分钟课的口播约 23 分钟（约 51%），略低于成本口径的 27 分钟。
