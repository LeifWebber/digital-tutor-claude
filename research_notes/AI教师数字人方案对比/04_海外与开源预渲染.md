## Q1. 输入形式：照片还是视频模板？能否直接用我们的 ElevenLabs MP3 做口型？

### Takeaway
「单张照片 + 外部音频」是 2026 年的主流 API 形态：Kling Avatar v2、OmniHuman 1.5/2.0、Mirage Avatar X、Hedra Character-3、InfiniteTalk、Wan2.2-S2V、EchoMimic 都直接吃「图 + MP3」，最贴合我们「一张老师照片 + ElevenLabs 音频」的流程。sync.so、LatentSync、MuseTalk 属于「视频 → 重新对口型」，需要先有一段老师的视频模板。Runway Act-Two 则是表演/动作驱动，不是音频驱动。

### Cited Findings
**照片 + 音频（image-to-video，无需训练）**
- Kling AI Avatar v2 Standard（fal）：必须同时提供图片和音频。图片支持 JPG/PNG/WebP/GIF/AVIF/HEIC；音频支持 MP3/OGG/WAV/M4A/AAC；可附带可选的文字 prompt；输出时长 = 音频时长；标注允许商用 — [fal Kling Avatar v2 Std](https://fal.ai/models/fal-ai/kling-video/ai-avatar/v2/standard)
- OmniHuman v1.5（fal）：必须提供 image_url 和 audio_url，同样支持 mp3；标签为 "Commercial use"/"Partner" — [fal OmniHuman v1.5](https://fal.ai/models/fal-ai/bytedance/omnihuman/v1.5)
- BytePlus OmniHuman（官方国际站）：输入为「单张图片 + 音频 + 可选文字 prompt」 — [BytePlus OmniHuman](https://www.byteplus.com/product/OmniHuman)
- Mirage（Captions）Avatar X API：输入为「视频或图片 + 音频」，输出视频 — [Captions API pricing](https://captions.ai/help/docs/api/pricing)
- InfiniteTalk（WaveSpeed）：image（必填）+ audio（必填）+ 可选 mask_image / prompt，分辨率 480p 或 720p — [WaveSpeed InfiniteTalk](https://wavespeed.ai/models/wavespeed-ai/infinitetalk)
- Wan2.2 Speech-to-Video 14B（fal）：prompt、image、audio 均为必填，音频支持 mp3 — [fal Wan2.2 S2V](https://fal.ai/models/fal-ai/wan/v2.2-14b/speech-to-video)
- ElevenLabs 已在自家图像/视频工具中上线 OmniHuman 1.5：上传头像图片和语音文件即可生成对口型视频 — [ElevenLabs OmniHuman 1.5 页面](https://elevenlabs.io/video/omnihuman-15)；第三方描述的操作流程见 [recapio 摘要](https://recapio.com/digest/elevenlabs-just-became-an-ai-video-generator-its-insane-by-the-zinny-studio)。注意：该官方页面的功能描述文字里还混入了 Veed Fabric、Sync 3 等其他模型名，像是模板复用，措辞需谨慎看待。
- ElevenLabs 另有独立的「Avatars」功能（ElevenCreative 内）：任意语音库声音（含克隆声音）+ 一个固定头像，一步生成对口型讲话视频；首发时不含 API，官方称 API 后续推出 — [ElevenLabs Avatars](https://elevenlabs.io/avatars?trk=test)
- Argil Avatars Audio-to-Video（fal）：只能用预训练好的模板头像，不能用自定义图片 — [fal Kling 页面的相关端点](https://fal.ai/models/fal-ai/kling-video/ai-avatar/v2/standard)

**视频 + 音频（对现有视频重新对口型，需要老师视频模板）**
- sync.so 全部模型（lipsync-1.9 / lipsync-2 / lipsync-2-pro / sync-3 / react-1）的输入都是带人脸的视频，文档中没有任何模型支持静态图片。lipsync-2 / 2-pro 要求视频中说话人有可见的动作，静止画面段不会被对口型 — [sync.so docs/models](https://sync.so/docs/models)
- LatentSync（fal）：必须提供 video_url 和 audio_url — [fal LatentSync](https://fal.ai/models/fal-ai/latentsync)
- MuseTalk（fal）：源视频（需有可见人脸）+ 音频；输出保持源视频的分辨率和帧率 — [fal MuseTalk](https://fal.ai/models/fal-ai/musetalk)
- InfiniteTalk 同样有 video-to-video 模式（WaveSpeed 提供 infinitetalk/video-to-video 端点）— [WaveSpeed InfiniteTalk V2V 文档](https://wavespeed.ai/docs/docs-api/wavespeed-ai/infinitetalk-video-to-video)

**模板 / 平台型（Studio 产品）**
- D-ID、Synthesia、Tavus、Akool、Colossyan、Elai 均基于平台头像（照片头像或训练出的数字分身）。Synthesia 提供「Voiceover Uploads」，即上传自己的配音代替文字脚本；但从抓取到的页面内容无法确认 Starter/Pro 套餐是否包含 — [Synthesia pricing](https://www.synthesia.io/pricing)
- SadTalker（3DMM）可由单张静态图片生成 — [tomodahinata 选型指南 2026-07](https://tomodahinata.com/en/blog/ai-lip-sync-talking-head-model-selection-guide-2026)

### Inferences
- 我们是「一张老师照片 + 现成 MP3」，首选 image+audio 类：Kling Avatar、OmniHuman、InfiniteTalk、Hedra、Mirage、Wan-S2V。
- sync.so / LatentSync / MuseTalk 适合「两段式」：先用 image+audio 模型或真人实拍得到一段 10–30 秒的老师「待机说话」视频，之后每张幻灯片只做低价的重新对口型。sync lipsync-2 约 $2.4–3/分钟，LatentSync 托管价不到 $0.5/分钟，比每次都从照片全量生成便宜。
- Runway Act-Two 的定位是由驱动视频把表演迁移到角色上（这是基于 Runway 产品定位的推断，本次未抓取其文档核实），不能单靠音频驱动，不适合本场景。

### Gaps
- 抓取到的页面没有说明 Hedra Character-3 API 的输入格式细节（官方 pricing 页面多次抓取均报 socket 错误）。
- Mirage 页面未写明音频是否可以外部上传（从「image + audio → video」的描述推断可以，但未明确）。
- D-ID Clips（presenter 模板）与 Talks（照片）的 API 输入差异，本次未能从官方页面获取。

## Q2. 输出质量（口型、头动、手势、长视频身份稳定）、最大时长、分辨率、背景

### Takeaway
目前没有覆盖全部模型的独立标准化评测。厂商自测与第三方对比的倾向是：Kling Avatar v2 与 OmniHuman 1.5 是 API 里口型和稳定性最好的一档（Kling 表情更丰富，OmniHuman 更稳）；InfiniteTalk 是低价的长视频选项，但侧脸和复杂辅音簇较弱，图生视频超过约 1 分钟会出现色偏。时长限制普遍偏短（Kling 讲话类约 1 分钟），按幻灯片切成 15–60 秒片段正好规避。

### Cited Findings
- PiAPI（厂商自测，2026）：OmniHuman 1.5 和 Kling Avatar 都能稳定生成，口型准确、画质高；OmniHuman 动作稳定性更好，Kling 情绪表现力更强；在基础口型测试中 Kling 略胜 — [PiAPI OmniHuman 1.5 vs Kling](https://piapi.ai/en/blogs/omnihuman-1-5-vs-kling-ai-avatar)
- Atlas Cloud（厂商博客）：Kling Avatar 在正脸讲话场景下的口型「是目前 API 中最稳定的之一」；InfiniteTalk 最便宜，弱点是侧脸参考图、密集辅音簇、背景细边缘 — [Atlas Cloud 指南](https://www.atlascloud.ai/blog/guides/best-ai-video-api-photorealistic-digital-human-faces)
- Kling Avatar v2：Standard 档讲话类最长 1 分钟（唱歌最长 5 分钟）；Pro 档为 1080p 选项，有聚合站称 1080p/48fps。以上均来自第三方，未在快手官方文档中核实 — [Hedra 的 Kling v2 Std 页面](https://www.hedra.com/models/video/kling/ai-avatar-v2-standard)；[Cliprise 指南](https://www.cliprise.app/learn/guides/model-guides/kling-ai-avatar-api-complete-guide)
- fal 称 Kling Avatar v2 Pro「面部细节更精细、口型更顺滑」，价格约为 Standard 的 2 倍 — [fal Kling 页面](https://fal.ai/models/fal-ai/kling-video/ai-avatar/v2/standard)
- OmniHuman 2.0（BytePlus）：原生 720p，输出时长 30–300 秒 — [BytePlus OmniHuman](https://www.byteplus.com/product/OmniHuman)
- InfiniteTalk（官方 GitHub）：480P / 720P；video-to-video 无长度上限；image-to-video 在约 1 分钟内效果好，之后色偏加重；默认 max_frame_num 为 40 秒（1000 帧）；FusionX LoRA（8 步）会加重 1 分钟后的色偏并削弱身份保持 — [MeiGen-AI/InfiniteTalk](https://github.com/MeiGen-AI/InfiniteTalk)
- WaveSpeed InfiniteTalk：单任务最长 600 秒（10 分钟） — [WaveSpeed InfiniteTalk](https://wavespeed.ai/models/wavespeed-ai/infinitetalk)
- Wan2.2-S2V（fal）：720p / 580p / 480p，16fps — [fal Wan2.2 S2V](https://fal.ai/models/fal-ai/wan/v2.2-14b/speech-to-video)
- sync.so：lipsync-2 / 2-pro 的面部分辨率为 512×512（pro 增强细节），sync-3 原生 4K；视频最长时长取决于套餐：Hobbyist 1 分钟、Creator 5 分钟、Growth 10 分钟、Scale 30 分钟 — [sync docs](https://sync.so/docs/models)；[sync pricing](https://sync.so/pricing)
- LatentSync 1.6：以 512×512 训练，减轻模糊；1.5 加入时序层，并改善了中文视频 — [bytedance/LatentSync](https://github.com/bytedance/LatentSync)
- MuseTalk：面部分辨率 256×256，单步潜空间修补；弱点是分辨率上限、抖动、细节身份，追求高画质需要叠加超分；HDTF FID 6.43 — [tomodahinata 2026-07](https://tomodahinata.com/en/blog/ai-lip-sync-talking-head-model-selection-guide-2026)
- Wav2Lip 面部 96×96，细节低；SadTalker 视频自然度偏弱；Hallo / EchoMimic 等扩散类表情和头动更自然，但慢 — [tomodahinata 2026-07](https://tomodahinata.com/en/blog/ai-lip-sync-talking-head-model-selection-guide-2026)
- EchoMimic v3 Flash：最高 768×768；超过 138 帧建议启用 Long Video CFG — [antgroup/echomimic_v3](https://github.com/antgroup/echomimic_v3)
- Tavus（新版定价页）：全部套餐 1080p，使用 Phoenix-4.5 全脸生成 — [Tavus pricing](https://www.tavus.io/pricing)
- Akool Talking Avatar 有 1080P 和 4K 两档（4K 价格翻倍） — [Akool API pricing](https://akool.com/api-pricing)

### Inferences
- 讲课场景以正脸、半身、少手势为主，正是 Kling / OmniHuman / InfiniteTalk 的强项。每张幻灯片 15–60 秒的切片长度在各家时长限制以内，也避开了 InfiniteTalk 超过 1 分钟后的色偏问题。
- 背景处理：调研到的 image+audio 模型都没有标注原生透明背景 / 抠像输出。实际做法应是让老师照片使用纯色或干净背景，渲染后再离线抠像（推断）。

### Gaps
- 没有找到任何独立、量化的跨模型口型基准（LSE-C/LSE-D、FID）覆盖 2026 年的商业 API。
- 背景移除 / Alpha 通道输出：所有页面均未提及，需要人工确认（D-ID、Synthesia 在平台内可能有背景替换功能，本次未核实）。
- Hedra Character-3、Mirage Avatar X 的最大时长和分辨率未能确认。

## Q3. 生成速度与价格（统一换算为 USD/每分钟输出）

### Takeaway
预渲染单价大致分四档（按每分钟输出）：
- **约 $1/分钟**：D-ID API、Tavus 视频超量、Synthesia 配音对口型
- **$1.8–3.6/分钟**：InfiniteTalk（WaveSpeed）、Kling Avatar v2 Std、Hedra、sync lipsync-2、Runway Act-Two
- **$4–10/分钟**：OmniHuman、Kling Pro、Mirage、Wan-S2V、sync-3/react-1
- **低于 $0.5/分钟**：托管 LatentSync，以及自部署开源

HeyGen API 参考价约 $3–4/分钟（Avatar IV）。速度方面，扩散类 image+audio 模型通常要 10–30 倍于实时，即渲染 1 分钟视频需 10–30 分钟（离线批处理可以接受）。MuseTalk 能实时，但需要视频模板。

## Q5. 印尼语口型

### Takeaway
没有找到任何针对印尼语的 AI 数字人口型公开评测。音频驱动模型基于声学特征（wav2vec / whisper），理论上与语言无关，但 InfiniteTalk 和 EchoMimic v3 Flash 使用的是中文 wav2vec2 编码器，LatentSync 1.5 专门针对中文做过优化。印尼语只能靠我们自己的 MP3 实测验证。

### Cited Findings
- OmniHuman 1.5 的托管页列出支持多种语言音频，包括中文、英语、日语、韩语、西班牙语和印尼语（厂商自述，无评测） — [Atlas Cloud 印尼语页](https://www.atlascloud.ai/id/models/bytedance/avatar-omni-human-v1.5)
- Kling Avatar v2 的语言支持说法冲突：一说口型针对英日韩中校准，一说 Standard 档与语言无关 — [Cliprise](https://www.cliprise.app/learn/guides/model-guides/kling-ai-avatar-api-complete-guide)；[Hedra Kling 页面](https://www.hedra.com/models/video/kling/ai-avatar-v2-standard)
- InfiniteTalk 的音频编码器为 chinese-wav2vec2-base — [InfiniteTalk GitHub](https://github.com/MeiGen-AI/InfiniteTalk)；EchoMimic v3 Flash 同样使用中文 wav2vec2 — [echomimic_v3](https://github.com/antgroup/echomimic_v3)
- LatentSync 1.5 改善了中文视频表现，未提其他语言 — [LatentSync GitHub](https://github.com/bytedance/LatentSync)
- MuseTalk 支持日语（使用 whisper 特征） — [tomodahinata](https://tomodahinata.com/en/blog/ai-lip-sync-talking-head-model-selection-guide-2026)
- 2026 年马朗穆罕默迪亚大学的一篇本科论文指出，多数口型系统使用英语 viseme 参数，用于印尼语时准确度仍是挑战（针对 3D 动画，非 AI） — [UMM eprints](https://eprints.umm.ac.id/id/eprint/29836/)
- Synthesia 定价页可见内容中未明确列出印尼语 — [Synthesia pricing](https://www.synthesia.io/pricing)

### Inferences
- 我们是「外部音频驱动」，不需要平台的 TTS 支持印尼语，只需要口型模型对印尼语语音的音素到口型映射足够好。印尼语音素体系相对简单，属于拉丁音系，无声调，风险预计低于声调语言，但双唇音 p/b/m、圆唇元音 u/o、快语速连读仍需实测。
- 中文 wav2vec 编码器对非中文语音一般仍然可用（社区普遍拿它跑英文 demo），但印尼语效果没有证据，需要列为重点测试项。

### Gaps
- 没有任何模型对印尼语给出 LSE-C/LSE-D 等量化评分；Reddit 和社区中也未检索到印尼语实测帖。
